# 古典音乐聆听档案｜第二阶段功能增量开发计划

> **用途：** 交给 Codex 在**已完成的第一阶段应用**上继续开发，不是新项目需求书。  
> **性质：** 增量 Plan / 功能扩展 / 分批验收。  
> **版本：** Phase 2 · 2026-11-04。  
> **前提：** 现有应用已经具备作曲家与作品目录、作品卡片、聆听标记与聆听日期管理等基础能力；具体实现以当前仓库为准。

## 0. 给 Codex 的执行总约束

1. **先读仓库，再动代码。** 检查 `package.json`、现有路由、数据库 Schema 与迁移机制、作品模型、目录数据导入流程、组件、测试。以实际代码为准，不预设文件名、框架版本或 API 已存在。
2. **禁止重新初始化或重复实现第一阶段。** 不重建首页、作曲家详情、已有聆听记录模块；仅在既有架构上增添所需功能和少量兼容性重构。
3. **保留全部本地数据。** 若改 IndexedDB Schema，采用数据库版本升级和非破坏性迁移；不得清库、重置聆听记录或用演示数据覆盖真实数据。涉及迁移，先提供备份/恢复路径，并以测试验证升级。
4. **一次只执行本文一个增量批次（P2-1、P2-2……）。** 不抢跑；每批完成后运行测试、总结并停止。
5. **作品以稳定内部 ID 关联数据。** 收藏、待听、公共标签、聆听记录都指向同一个作品 ID，不直接以 `K.551`、作品名、API 排序位置或第三方源 ID 当唯一主键。
6. **核心统计口径不变：** “已听作品数”=已完整聆听且属于独立可计数作品的**去重数量**。部分聆听不计数；播放次数不代替作品数；合集、乐章等默认不得重复计数。
7. **公开信息与个人行为分离。** 热门、推荐和代表作品是公共资料字段；“我喜欢”“关注”“待听”是个人数据，两者互不覆盖。
8. **无依据不造数据。** 不捏造热度分、排名、代表作品数量；缺来源时宁可显示“暂无数据”。所有引用的公共标签保留来源与更新时间或数据版本。
9. **离线优先。** 公共标签可以从合法来源在导入阶段离线构建为本地数据，不强迫用户每次打开作品页联网。遵守源站 API 规则和数据许可。
10. 每批输出：完成内容、改动文件、数据库迁移情况、测试命令及结果、已知限制、下一批入口；如发现与此文冲突的既有实现，先陈述冲突并采用最小破坏方案。

## 1. 第二阶段目标与范围

本阶段把既有“作品聆听记录簿”扩展为**可收藏、可探索、可统计的个人古典音乐作品目录**。用户应能方便地回答：

- 我关注/喜欢哪些作曲家？喜欢哪些作品？
- 我打算下一步听什么？
- 某位作曲家的热门作品、资料库推荐作品有哪些，其中还有哪些未完整听过？
- 我完整听过多少部**不同**作品，分布于哪些作曲家、体裁和年份？
- 对某位作曲家的代表作品，我已经完整听过多少部？

### 本阶段确定要做

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 个人标记 | 关注作曲家、喜欢作曲家 | 两个独立标记；首页快捷筛选 |
| 个人标记 | 喜欢作品、加入待听 | 两个独立标记；支持统一检索 |
| 公共标签 | 热门、资料库推荐、经审核的代表作 | 允许同一作品多个标签，附来源 |
| 探索 | 未听过的热门/推荐/代表作品 | 与现有听过状态、搜索、排序协同工作 |
| 统计 | 全局数量、按作曲家、按体裁、按首次聆听年份 | 数据真实、口径明确 |
| 图表 | 柱状图、环形/饼图、按年趋势、作品探索矩阵 | 过滤条件一致，空数据不报错 |
| 兼容 | 持久化、迁移、备份恢复、回归测试 | 已有数据不能丢 |

### 明确不在本阶段

音乐播放器与流媒体、演奏版本库、演奏家推荐、自动记录播放时长、复杂个性化算法、社交、AI 自动评判艺术价值、移动端原生开发、账号同步、打卡游戏化。文本笔记及演奏版本可作为远期扩展，不阻塞本阶段。

## 2. 新功能的精确行为

### 2.1 个人收藏与待听

- **关注作曲家**：用于首页快速进入；不代表喜爱。作曲家卡片和详情页可切换关注。
- **喜欢作曲家**：与关注独立，可在“我的收藏”集中查看。可同时关注且喜欢。
- **喜欢作品**：任何聆听状态的作品都能收藏；不要因为“未听过”禁止收藏。
- **待听作品**：任何作品都能手动加入或移除。完成聆听时**不自动删除**待听标记；可以出现非强制提示“已完整听过，是否移出待听？”
- **入口**：保留现有首页与详情页，在作曲家卡片上增加小型关注/喜欢控件；作品卡片增加爱心和待听入口（空间不足可放弹窗/菜单）；新增“我的收藏/待听”聚合页面或选项卡。
- **操作**：点击立即生效并持久化；重复切换幂等；导航、刷新、重新打开页面后仍正确；同一项出现在多个页面时状态同步。
- **搜索**：支持按作曲家、作品名、编号检索收藏和待听项，使用既有搜索实现或其适配层；不得因为收藏筛选改变原始目录排序规则。

### 2.2 热门、推荐、代表作标签

严格区分三者：

| 标签 | 展示名 | 判定规则 | 允许的数据来源 |
| --- | --- | --- | --- |
| `popular` | 热门 | 公开数据集明确的热门标记，或可追溯的演出/聆听热度证据 | 首版优先 Open Opus 的 `popular` 等现成字段 |
| `recommended` | 资料库推荐 | 数据源明确标记“推荐”；**不能直接称为音乐史代表作** | 首版优先 Open Opus 的 `recommended` |
| `representative` | 代表作 | 有可说明的编选标准和可核对来源，经校验/人工审核 | 日后加入经过核对的作品指南或多源证据 |

要求：

- 不自动把 `recommended` 映射成 `representative`。
- 标签可以重叠，但与“我喜欢”完全无关。
- 不设置固定的“每位作曲家 Top 20”，不强编 0–100 分热度，不依赖单条录音播放量判定抽象作品的整体热度。
- 每个标签至少记录：**作品稳定 ID、标签类型、数据源、来源标识/URL（若有）、数据版本或采集日期、审核状态**。无可靠证据不展示。
- 某个外部 API 的曲目无法确定对应本地哪部作品时，暂存“待匹配”，不能仅以同名强行关联，尤其注意同名作品、不同目录版本与一部作品的多个录音。
- 公共目录更新应采用增量合并；更新或撤销标签不触碰用户聆听、收藏与待听记录。

**第一版策略：** 优先复用仓库已存在的作品数据源。如果仓库已引入 Open Opus，从其 `popular/recommended` 字段映射并保留来源；如未接入，不为了本阶段改写全部作品目录。只实现稳定的标签数据模型与可复用导入器，能匹配的作品才显示标签。`representative` 若缺审核资料则暂时不生成标签，界面显示“代表作数据尚未建立”。

### 2.3 探索筛选

在作曲家作品页扩充筛选（按现有 UI 习惯，尽量不堆叠太多控件）：

- 全部作品 / 已完整听过 / 部分听过 / 未完整听过。
- 热门 / 资料库推荐 / 代表作（数据存在才有内容）。
- **未完整听过的热门作品**、未完整听过的推荐作品、未完整听过的代表作。`partial` 也属于“未完整听过”。
- 喜欢作品 / 待听作品。

可以使用组合过滤器而不是为每种组合造单独页面，例如「聆听状态=未完整听过」+「公共标签=热门」。筛选结果有数量，并与搜索一起生效；无结果时给清晰空状态。

### 2.4 统计口径与图表

**核心不变量：** 统计针对**作品**而不是录音、乐章播放事件或聆听次数。

- `completedDistinctWorks`：状态为 `completed` 且属于独立可计数单位的作品 ID 数量，按 ID 去重。
- `partialWorks`：部分听过的独立可计数作品数量，单独展示，不计入已听。
- `composerCoverage`：某作曲家完整听过的可计数作品数 / 该作曲家**已入库、可计数、可聆听的作品数**。如果目录明显不完整，应标注“基于当前收录”，不能宣称完成该作曲家全部作品。
- `popularCoverage`：完整听过且有热门标签的可计数作品数 / 有热门标签的可计数作品数。
- `recommendedCoverage`：同理，仅针对推荐标签。
- `representativeCoverage`：只有形成**明确来源、范围与版本**的代表作品集合后才计算；集合不存在时展示“暂无代表作品数据”，不能用推荐作品替代。
- `byComposer`：按作曲家统计已完整听过的不同可计数作品数量（柱状图，支持从高到低排列）。
- `byGenre`：按作品**主要体裁**统计；先保证每个作品在体裁饼图中只计一次。体裁缺失划入“未分类”，不擅自推断。
- `firstListenByYear`：根据同一作品**已确认的最早完整聆听日期**确定年份，支持日期精度为 `YYYY`、`YYYY-MM`、`YYYY-MM-DD`；日期未知的不进年度图，单独显示“年份未知”。**导入/录入日期不是聆听日期**。
- 如果一个作品被听过十次，已听作品数量依然是 1；不要用聆听事件总量替代。
- `collection`/合集容器和不独立计数的 `movement`/乐章默认不参与作品数。若已有仓库缺计数策略，可在统计适配层引入显式映射/例外配置，不要凭“叶节点都算作品”推断；**不要在本阶段全面重做第一阶段作品层级模型**。

**图表：** 首页提供少量简明数字；独立统计页展示作曲家柱状图、体裁占比图、首次聆听年度趋势、热门/推荐/代表作品覆盖率。优先使用项目现有图表库；没有时再选择轻量库。图表有对应数据列表或可访问说明，避免只有图形难以查数。

### 2.5 作品探索矩阵（最后实现）

- 行是作曲家，列是该作曲家的作品编号顺序或分组；不能强制不同作曲家共用一套编号刻度。
- 每个单元按“已完整听过 / 部分听过 / 未听过”呈现；喜欢作品、热门标签可用小标识或悬浮信息叠加，不能只靠颜色区分。
- 点击单元进入既有作品详情或弹窗；长目录采用分组、分页或虚拟列表，避免全量几千节点同时渲染。
- 第一版只做**单个作曲家矩阵视图**更稳妥；跨作曲家全局矩阵可后移。

## 3. 数据模型：只新增必要字段/表，不推翻旧模型

> 下列为**逻辑结构**，不是强制要求新建同名表。Codex 应选择符合现有 Dexie/IndexedDB/其他持久层结构的最小变更。

```ts
// 与现有 Composer / Work 用稳定 ID 关联。
interface ComposerPreference {
  composerId: string;
  isFollowing: boolean;
  isFavorite: boolean;
  updatedAt: string;
}

interface WorkPreference {
  workId: string;
  isFavorite: boolean;
  isInListenLater: boolean;
  updatedAt: string;
}

type PublicLabelType = 'popular' | 'recommended' | 'representative';
interface PublicWorkLabel {
  id: string; // 标签记录自身 ID / 唯一键
  workId: string;
  type: PublicLabelType;
  source: string; // 如 open-opus / curated-guide
  sourceRef?: string; // URL / 来源曲目 ID / 文献标识
  sourceVersion?: string;
  recordedAt?: string;
  reviewed: boolean; // representative 需要 true 才对外展示
}
```

**约束：**

1. `composerId`、`workId` 引用现有稳定主键；更新作曲家/作品展示名不改变个人标记。
2. 同一用户与同一作曲家/作品仅一条偏好记录（本地单用户版本不必引入账号 ID）；标签唯一性可采用 `(workId, type, source, sourceRef)`。
3. 初始默认值为 `false`，没有用户记录不算错误；不必为所有作品预插入默认偏好行。
4. 公共标签表支持多个来源同一标签，展示时去重；若未来需合并来源，不能误删其他来源证据。
5. IndexedDB 升级中只新增 schema/index 并迁移真正需要迁移的字段，不覆盖原有听过状态、日期和作品表。
6. 备份导出要包含偏好与公共标签来源元数据（或包含公共目录版本供复现）；旧版备份导入需要兼容新增字段缺省。
7. 删除/合并作品时，若已有重定向或去重机制，应同时处理个人标记和标签关联，避免孤儿记录。

## 4. 实施顺序：5 个可独立交付的增量批次

### P2-1｜个人收藏与待听清单（先做）

**任务**

1. 审查现有作曲家/作品存储结构、导航、卡片、备份工具与测试。
2. 添加作曲家关注/喜欢、作品喜欢/待听的持久化结构及访问接口；执行非破坏性升级。
3. 在现有作曲家卡片/详情、作品卡片/弹窗添加独立操作，保证键盘可用、文字/图标有明确状态。
4. 添加“我的收藏”聚合页/入口，可切换“关注作曲家、喜欢作曲家、喜欢作品、待听作品”，支持既有搜索方式。
5. 备份/恢复新增标记；完成持久化和回归测试。

**验收**

- 关注与喜欢一位作曲家可以同时开启/单独关闭。
- 作品喜欢与待听互相独立，不影响聆听状态与日期。
- 刷新、重新打开、跳转不同页面，标记保持一致。
- 原来的聆听记录和作品目录完全保留；旧数据库升级后数据一致。
- 导出再导入后新旧记录均保留，旧备份导入不报错。

**Codex 指令**

> 阅读当前仓库和 `PHASE2_INCREMENTAL_PLAN.md`。只执行 **P2-1 个人收藏与待听清单**，以当前已完成应用为基础，禁止重新初始化或重写第一阶段。先检查并复用现有数据库、路由、卡片、搜索与备份接口。实现最小增量、非破坏性迁移和测试。完成后给出改动文件、测试结果、数据保留验证，停止，不执行 P2-2。

### P2-2｜热门/资料库推荐/代表作数据接入

**任务**

1. 识别仓库现有作品数据源和可用的目录编号、第三方 ID 映射。
2. 新增公共标签及来源元数据的存储/导入/查询机制，处理增量更新与去重。
3. 首先复用现成数据里的 `popular`、`recommended`（如实际源可用）；对于缺失或无法匹配的作品保留未分类状态。**不要把 `recommended` 自动叫做“代表作”。**
4. 建立 `representative` 经审核后才展示的机制；本阶段可以没有任何代表作数据，不得编造清单。
5. 在作品卡片/弹窗显示已有的公共标签；点击标签可看到来源或简明来源说明。
6. 加入导入匹配报告：匹配成功数、无法匹配数、冲突数。对歧义项不自动关联。

**验收**

- 标签显示有据可查，公共标签变化不影响个人偏好和聆听记录。
- 多来源同类标签在 UI 上显示为一个标签，仍可查看来源。
- 无数据不显示假排名/百分比；不把普通作品自动判定为不值得听。
- 重复导入相同数据无重复/混乱记录。

**Codex 指令**

> 仅执行 `PHASE2_INCREMENTAL_PLAN.md` 的 **P2-2**。检查项目实际使用的目录数据源，在不替换已有作品目录的前提下增加公共作品标签与来源元数据。优先使用数据源已有 `popular/recommended` 标记；`representative` 只接受有来源且已审核的集合。实现去重和歧义匹配保护，补充测试。完成后停止。

### P2-3｜作品探索筛选

**任务**

1. 在既有作曲家作品列表上加入热门、推荐、代表作品筛选，及“未完整听过”组合条件。
2. 增加喜欢/待听过滤，保留现有搜索、编号排序、分页/虚拟滚动和日期操作。
3. 在作曲家详情上提供“未完整听过的热门作品”快捷入口；如无公共标签，明确空数据原因。
4. 提供符合现有设计风格的标签计数与空结果状态。

**验收**

- `partial` 与 `unheard` 都包含在“未完整听过”中，`completed` 不包含。
- 搜索、状态过滤、公共标签过滤可以正确组合；切换后聆听记录不改变。
- 大型作品目录筛选仍流畅，刷新后数据完整。

**Codex 指令**

> 仅执行 **P2-3 作品探索筛选**。复用现有作品列表与筛选模块，新增公共标签和个人收藏过滤以及“未完整听过的热门/推荐/代表作”快捷筛选。不得重建页面或修改已存在的聆听业务规则。补充组合筛选测试并停止。

### P2-4｜统计数据层与可视化

**任务**

1. 实现可单元测试的统计选择器/查询层，不将统计计算散落在图表组件里。
2. 统计去重已听作品数、部分听过数、按作曲家/体裁、首次完整聆听年份、热门/推荐/代表作品覆盖率。
3. 按需增加统计页面和轻量图表（柱状图、饼图或环形图、年度柱状/折线）；首页可选择少量总览数据。
4. 对目录不完整、体裁未知、日期未知、代表作品集合不存在、分母为零提供准确说明与空状态。
5. 为关键口径添加测试样本：同作曲家多作品、同作品多日期、partial、合集与乐章、无年日期、重复公共标签。

**验收**

- 一首作品听十次依旧计 1；部分听过计 0；合集不重复计入。
- 一部作品若只知首次聆听年份，按该年份统计；日期不详不凭录入日填入年度图。
- 所有占比图分母清晰；0/0 不显示 NaN 或虚假的 100%。
- 图表数据与其对应的明细列表一致。

**Codex 指令**

> 仅执行 **P2-4 统计数据与可视化**。先读现有作品层级、聆听状态、日期模型，再编写独立可测的统计层，确保只统计已完整听过的独立作品。实现作曲家柱状图、体裁分布、年度趋势、公共标签覆盖率及明确空状态。测试必须覆盖去重、部分听过、父子作品和未知日期。不要开发 P2-5。

### P2-5｜作曲家作品探索矩阵 + 整体验收

**任务**

1. 在单个作曲家页面增加可切换的“列表 / 探索矩阵”视图。
2. 以该作曲家作品的既有正确编号顺序或分组方式排列单元；颜色/形状区分已完成、部分、未听，收藏与公共标签用额外标记或说明表示。
3. 点击单元进入同一套作品详情与聆听日期编辑，不重做详情逻辑。
4. 对大量作品采用分组、窗口化或分页；保障键盘可达、文本提示和窄屏可用性。
5. 端到端测试个人收藏 → 热门筛选 → 标记已听 → 统计更新 → 备份恢复的完整路径。

**验收**

- 矩阵与列表使用同一作品数据和状态；更改状态后两个视图及时一致。
- 大量作品时不会一次渲染所有单元而造成明显卡顿。
- 新功能回归后原作品查询、编号排序、日期修改、备份功能仍正常。

**Codex 指令**

> 仅执行 **P2-5 探索矩阵与回归验收**。在单个作曲家详情增加矩阵视图，完全复用当前作品状态/收藏/标签和详情编辑；保障大型目录性能与可访问性。回归测试包含新旧功能和 IndexedDB 备份恢复。完成后汇总第二阶段新增功能、遗留风险与未来可选方向，停止。

## 5. 跨批次验收样例（必须能测）

| 场景 | 正确行为 |
| --- | --- |
| 喜欢莫扎特但不关注莫扎特 | 出现在“喜欢的作曲家”，不出现在“关注”清单 |
| 喜欢贝多芬 Op.61 且尚未听完 | 可以收藏；已听作品数不变 |
| 待听作品被标记为完整聆听 | 已听数 +1；待听标记保留，允许手动移除 |
| 某作品同时热门和推荐 | 显示两个标签；热门数量与推荐数量分别计算；个人作品总数仍算 1 |
| 数据源推荐一首作品 | 可标记“资料库推荐”，**不能**无依据标记“代表作” |
| 第九交响曲只听过第四乐章 | 整部最多为 `partial`，已听作品数为 0 |
| Op.28 前奏曲作品集与其中 3 首独立前奏曲 | 若作品集是容器，则只统计已听的 3 首，不把作品集多算 1 |
| 同一作品录入 2019、2021 两次完整聆听 | 已听总数为 1，首次聆听年份计入 2019 |
| 录入“2019年听过”，具体日不详 | 2019 年度统计可计入；不得伪造月份和日期 |
| 作品热度标签数据缺失 | 显示“暂无标签数据”，不自动认为该作品不热门 |
| 老用户从上一版数据库升级 | 历史聆听状态、日期及作品目录保留；新增字段按默认值工作 |
| 删除公共标签重新导入 | 不影响喜欢、待听和聆听记录 |

## 6. 推荐的 UI 导航调整（以现有布局为准）

优先保留第一阶段页面，只在现有结构中增加以下入口：

- **作曲家目录**：原有主入口，作曲家卡片上可关注/喜欢。
- **我的收藏**：关注的作曲家 / 喜欢的作曲家 / 喜欢的作品 / 待听清单。

注意：不要把“热门作品”与“我的最爱”混在同一个标签组里；公共属性和私人属性的含义不同。
