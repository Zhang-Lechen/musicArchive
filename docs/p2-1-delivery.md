# P2-1｜个人收藏与待听清单交付

日期：2026-11-04。依据 `plans/classical-listening-phase2-incremental-plan.md`，本轮范围为下一增量批次 P2-1。

## 完成内容

- 首页作曲家卡片、作曲家详情提供独立的关注与喜欢按钮，首页增加“全部 / 已关注 / 已喜欢”筛选，与原搜索、音乐时期组合生效，保持目录原排序。
- 作品卡片及现有详情弹窗提供独立的喜欢、待听按钮，包括未听、部分听过和不独立统计的目录条目。个人标记不改变聆听状态或日期；完成、重置或撤销聆听均不自动移出待听。
- 顶部“我的收藏”进入 `/collection`。四类清单带总数量，支持作曲家中文/原文名、别名、作品名称与编号变体检索；作品按作曲家、既有编号顺序显示，每页最多 36 条，作曲家最多 24 张卡片。
- 聚合页复用原作品卡片与日期弹窗，可记录今天、编辑历史日期、撤销聆听。移出待听后若还喜欢作品，作品仍保留在喜欢清单，目录条目不删除。
- 标记通过显式设值事务持久化，事务读取最新记录后只更新一个标记，避免两个字段并发操作互相覆盖；重复设为相同值不写入，也不改变更新时间。读不到偏好视为全部 false，不批量插入默认行。
- 按钮支持键盘与 `aria-pressed`，保存中禁用当前按钮，失败显示原因并可重试。按钮与导航链接分开，收藏操作不会误打开详情。Dexie 实时查询同步各页面及同源标签页。
- 复用 A1 已有的完整备份与 v1/v2 兼容恢复，补齐导出说明及预览中的关注、喜欢、待听数量。

## 数据与兼容

- **无新 schema 版本、无新增迁移。** 当前 A1 已发布 IndexedDB v2，现成 `composer_preferences` / `work_preferences` 及备份格式 2 足以实现本批功能。
- 计划逻辑名称 `isInListenLater` 对应当前仓库的 `isInQueue`；保留既有字段，避免重命名导致旧偏好或备份不兼容。始终按稳定内部 composerId/workId 关联。
- 没有修改目录快照、用户数据、原数据库版本定义或来源标签；测试仅操作独立 fake-indexeddb 或 Playwright 隔离浏览器档案。
- v1 升级回归验证作品、进度、日期 ID/精度及元数据保留，并覆盖异常升级事务回滚。v2 重开和导出恢复验证偏好、作品、历史日期同时保留。
- 备份入口仍是“数据与备份 → 导出 JSON 备份”。恢复仍需先预览、勾选替换确认再执行事务；旧格式 1 可读取，未提供的偏好默认为 false。恢复旧备份会以备份内容替换当前档案，不自动保留备份之后的新标记。

## 统一验收要点

1. 在首页同时关注、喜欢莫扎特；切换“已关注”可找到他。进入详情取消关注，喜欢保持开启；“我的收藏”中关注清单消失、喜欢的作曲家仍在。
2. 搜索 `K551`，在未听过状态下同时喜欢、加入待听。进入“我的收藏 → 待听清单”，依次搜索 `莫扎特`、`KV 551`、`朱庇特` 都能找到作品。
3. 在待听清单点击聆听，再打开记录日期弹窗调整历史年份；待听仍开启。手动移出待听后，喜欢的作品及历史日期仍保留。
4. 在同源第二个标签页打开清单，切换标记观察目录和清单同步；刷新、关闭重开后仍保留。
5. 导出完整 JSON，在另一个测试浏览器档案从“数据与备份”预览、确认恢复，核对关注、喜欢、待听及日期均一致。测试恢复会替换目标档案，请使用测试档案。
6. 320px 窄屏可操作分类、搜索、标记和日期弹窗，页面没有横向溢出。

## 已知限制与下一批入口

- 个人档案仍限当前浏览器、当前 origin，无账号同步；请定期备份。
- 清单搜索是当前页面的临时状态；刷新会重置搜索，分类地址可直接打开。多作曲家清单先按作曲家分组，再沿用编号排序，不建立跨作曲家的统一编号刻度。
- `partial` 的三态数据能力沿用 A1，本批不新增聆听状态筛选或调整旧 UI 的状态展示；这属于 P2-3 的范围。
- 公共热门、推荐、代表作接入，探索组合筛选、统计图表和矩阵分别属于 P2-2 至 P2-5，本轮不提前执行。
- 下一批为 **P2-2 热门 / 资料库推荐 / 代表作数据接入**，应复用现有 Open Opus 快照、来源映射和公共标签表；推荐不得直接映射为代表作。
