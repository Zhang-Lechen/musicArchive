# 古典音乐聆听档案

Classical Listening Archive · 本地优先的古典音乐作品目录与个人聆听档案。

按根目录 `PLAN.md` 完成阶段 0—11。`PLAN.md` 是用户指定的原始文件 `classical-listening-app-development-plan.md` 的原文副本，两者保持一致；用户已授权连续完成后统一验收。决策与约束记录在 `docs/decisions.md`。

## 运行

需要 Node.js 22.14+（22.x）、24.x 或 26+，npm 10+。当前验证环境是 Node.js 22.14.0 / npm 10.9.2 / Windows。

```sh
npm install
npm run dev
```

打开终端显示的地址（默认 `http://localhost:5173`；占用时 Vite 会选择下一个端口）。按 Ctrl+C 停止。

```sh
npm run lint
npm run typecheck
npm run test
npm run build
npm run preview
```

`test` 为一次性运行，`test:watch` 为监听模式。`format` 格式化，`format:check` 检查格式。`npm ci` 可根据 lockfile 干净安装。项目 `.npmrc` 使用官方 HTTPS 源及项目内 `.npm-cache/`，不要求管理员权限。

## 当前功能

- 首页显示真实 IndexedDB 作曲家、中文/原文名、生卒年、时期、主目录与已听过进度；支持作曲家搜索与时期筛选。
- P2-1：作曲家可独立关注、喜欢，首页可按个人标记筛选；作品卡片与详情可独立喜欢、加入待听。完成聆听不会自动移出待听。
- 主体一级导航统一为“作曲家”(`/composers`)、“我的收藏”(`/favorites`)、“聆听统计”(`/statistics`)；首页 `/` 保持可用，旧 `/collection` 地址保留查询条件跳转至收藏。支持刷新和浏览器前进、后退。
- “我的收藏”汇集关注的作曲家、喜欢的作曲家、喜欢的作品及待听清单；支持名称、别名、编号搜索，作品按作曲家与原有编号规则排列，分页显示并复用原日期编辑。
- 首页使用紧凑 Hero，桌面标题单行、首屏可见作曲家；右侧真实已听数量可点击进入统计，支持键盘和悬停提示。
- 聆听统计展示完整听过、部分听过、已听作曲家数量和总体覆盖率；提供作曲家前十横向柱状图（作品数/覆盖率排序、可进入目录）、目录体裁环形图、首次完整聆听年份柱状图。统计查询只读，随本地及跨标签页记录变化更新。
- 统计按稳定作品 ID 去重，沿用可统计作品资格，仅 `completed` 计入完整数量和覆盖率；乐章、作品集容器及不符合资格的作品不计入。年份取手动录入的最早已知完整聆听日期，支持年/月/日精度，不使用创建时间。无有效日期单独统计；不详与已知日期并存时使用已知日期。体裁优先 `primaryGenre`，其次 `genre`，缺失归“其他/未分类”，不按名称猜测。零数据展示空状态。
- 作曲家目录支持编号、名称、别名搜索（`K551` / `K. 551` / `KV 551` / `朱庇特`），听过状态与体裁联合筛选、编号或名称排序。
- 作品以稳定内部 ID 关联，支持多编号、目录版次、别名、存疑/片段/佚失状态、父子作品和乐章。主列表每页最多 36 张卡片，可显式显示子作品；首页每页最多 24 位作曲家。
- 快速“聆听”在单个事务中标记已听过并记录浏览器本地今天，同日不重复，提供撤销。
- 已听过的作品卡片直接显示“最近聆听日期”，按实际聆听日期而非录入时间取最近值，保留年/月/日精度；没有已知日期时显示“日期不详”，记录修改或删除后自动更新。
- 弹窗支持年、年月、年月日、不详四种精度，历史日期增改删，未来日期与重复记录校验。删除最后一条日期仍保持已听过，恢复未听过要确认并清空日期，可撤销。
- 多选作品可批量记录今天或标记日期不详，支持撤销；其他页面和标签页的进度同步更新。撤销会检查版本快照，避免覆盖后续修改。
- 手动补录有名称和编号冲突检查，可填写别号、层级与目录状态；后续来源导入优先通过可靠映射或无歧义编号关联。
- UTF-8 JSON 完整备份、预览与确认恢复；运行时校验格式版本、字段、ID 引用、日期、主编号、层级循环和进度不变量，同作品/同精度/同日期默认合并。恢复失败事务回滚。
- 目录 JSON 导入是单独的元数据合并入口，预览后确认，不清除个人进度与日期。
- 生产构建包括离线应用壳；正常使用不依赖外部 API，无后端和账户。

## 数据范围与可信度

内置 Open Opus CC0 快照：**220 位作曲家、25,195 条作品**，含常见七位作曲家。全部扩展目录标为 `partial`，页面明确提示“目录完整性未验证”。数量是当前来源中的条目数量，**不代表历史上的完整作品总数**。

另保留首批 `sample` 种子：7 位作曲家、18 部作品，其中 12 部莫扎特核心作品有逐条核对链接与中文译名。初始化与升级均幂等，不覆盖个人档案。其他作品保留可读原文，未补造中文名、调性、编号或目录版次。

`docs/data-sources.md` 说明许可、核对来源、时间、映射及音乐学限制。`docs/catalog-report.json` 包含 **15,001 项复核任务**；主要为缺少可识别编号，另有名称/编号冲突和复杂修订号。未经过全量专业人工审校，不声称覆盖所有作曲家或完整莫扎特目录。

默认统计主层级独立作品，排除乐章、子作品、作品集和明确佚失条目；存疑或未完成作品有文字标识。不会推断整部作品和乐章之间的听过状态。来源未提供的层级不会自动猜测。

## 存储与备份

Dexie 当前 schema v2 显式定义在 `src/db/database.ts`，保留 v1 并提供非破坏性升级。A1 已建立偏好表，P2-1 直接复用，不追加版本或重写用户数据。IndexedDB 是主存储，UI 只保存搜索、筛选、选择与弹窗等临时状态。日期、聆听状态、个人标记均由仓储事务执行。

数据属于**当前浏览器、当前站点地址（origin）**。不同端口、浏览器、浏览器档案或设备互不共享数据。浏览器清理站点数据、无痕窗口结束、存储配额回收和设备损坏可能导致丢失，**请定期通过“数据与备份”导出 JSON**。service worker 缓存不是个人数据备份。

恢复备份会替换当前档案，必须勾选确认并点击替换按钮；导入错误或事务写入失败不会清空原数据。备份文件大小上限 100 MB。显式恢复的空档案不会在刷新后被种子重新填充。恢复后也不会自动合并内置目录，若需要扩展可通过目录导入入口显式更新。

schema 升级必须追加 `version(n).stores(...).upgrade(...)`，不能修改已发布版本。备份 `formatVersion` 当前为 2，包含关注、喜欢、待听和公共标签来源资料，兼容读取缺少新字段的 v1 备份；旧版应用不能读取 v2 备份，回退前请保留旧备份。恢复旧备份会以该备份为准替换档案，缺省标记为 false。目录数据版本单独管理。未来同步可通过 `CatalogProvider` 接入，但当前未实现云同步。

## E2E 与离线验收

```sh
npm run test:e2e
```

命令先构建，再启动独立预览服务器 `http://127.0.0.1:4175` 并运行 Playwright。默认使用已安装 Microsoft Edge Chromium，不读取用户档案。每个用例都有独立上下文，浏览器重启测试使用 `test-results/` 中专用临时档案，测试结束关闭。HTML 报告在 `playwright-report/`。

其他操作系统或希望使用 Playwright Chromium 时：

```sh
npx playwright install chromium
```

PowerShell：`$env:PLAYWRIGHT_CHANNEL = 'chromium'; npm run test:e2e`。POSIX shell：`PLAYWRIGHT_CHANNEL=chromium npm run test:e2e`。

测试覆盖完整聆听路径、2019 年历史记录、删除后状态、恢复与撤销、坏备份、跨档案恢复、手动补录、层级、分页、跨标签同步、3000 条隔离测试目录、320px 布局、离线读写和浏览器重启。合成性能数据只存在于隔离测试上下文，不在交付目录或应用种子中。

离线能力仅在**生产构建预览或 HTTPS 部署**中启用，开发服务器不注册 service worker。先联网打开一次并等待页脚“离线已就绪”，再断网刷新并访问目录、写记录。生产离线缓存只缓存应用与内置目录，不缓存或上传用户档案。更新采用默认 service worker 等待机制，关闭旧标签页后启用新版本，不强制打断正在编辑的页面。

静态部署需配置 SPA 回退：非静态资源路径返回 `index.html`。Vite 开发与预览服务器已提供该行为。根路径部署受支持，子路径部署需同时调整路由 basename、静态资源与 service worker scope；本次未发布外部网站。

## 目录工具

```sh
npm run catalog:check
npm run catalog:build
npm run seed:build
```

上述命令重放本地快照；`catalog:check` 为 dry-run，不改变应用目录。`npm run catalog:fetch` 才会请求第三方 API，更新原始数据并输出规范化目录。限速、重试、错误报告、许可和手动复核流程见 `scripts/README.md`。

## 已知风险与范围外

- 全量目录仍有待复核项，复杂目录版次、范围号、作品集粒度和归属有持续审校需求。
- 开发依赖审计有 13 条中危提示，根因是开发工具的 minimatch glob 拒绝服务漏洞；生产依赖审计为 0。避免将不可信输入作为 lint glob，跟进上游修复；未使用强制降级或未验证的跨主版本覆盖。
- jsdom 的传递依赖 `whatwg-encoding` 有弃用提示，当前测试正常。
- 本次 E2E 验证 Windows Edge Chromium；Firefox、Safari 和真实移动设备还需要额外兼容性验收。
- 没有音乐播放、演奏录音版本、账户、后端、评分、乐评、社交或推荐。原生移动端、云同步属于 PLAN 明确保留的未来范围。

统一手工验收清单见 `docs/acceptance.md`；P2-1 增量交付与验收要点见 `docs/p2-1-delivery.md`。本轮止于 P2-1，后续批次从 P2-2 公共标签数据接入开始。
